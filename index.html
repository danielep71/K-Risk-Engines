02 / A common review approach

Turn a comparison into an explanation.

A matching result is useful evidence. Understanding why it matches—or why it differs—is the purpose of the review.

  1. 01

    Align the inputs

    Reconcile data, scope, conventions and assumptions. Establish that both calculations answer the same question.

  2. 02

    Trace the calculation

    Compare intermediate quantities and test sensitive assumptions. Locate the source of a difference before judging the final number.

  3. 03

    Record the evidence

    Retain the model version, inputs, reference results and explanations. Document unresolved differences and the limits of the conclusion.

Agreement with a benchmark supports a review; it does not, by itself, establish model validity or regulatory compliance.

03 / About the project

One entry point.
Independent projects.

K-Risk Engines brings together tools developed by Daniele Penza to make financial risk calculations easier to inspect, reproduce and challenge.

The collection is intended for practitioners reviewing bank models and calculations, auditors examining implementation, advisors investigating differences, and researchers and students exploring methodology.

This repository hosts the project overview and website. Each model repository owns its implementation, detailed documentation, issues, tests and releases.

Portfolio direction

Develop each model on its own evidence.

  • Explore todayUse the existing SA-CCR release and inspect the IRRBB development and FRTB-SA prototype repositories.
  • Build nextDevelop the prepayment project with an explicit modelling scope and validation plan.
  • Keep the family consistentMaintain clear naming, familiar workbook presentation and visible methodology and evidence across the collection.

This is a direction of travel, not a delivery commitment. Detailed milestones remain in each repository.
